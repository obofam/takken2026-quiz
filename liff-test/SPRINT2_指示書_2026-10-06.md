## 1. ゴール（これが動けば完了）

1. **テスト購入**：ログイン済みの利用者が「学習カルテを試す（テスト決済）」を押すと Stripe Checkout（テストモード）が開き、テストカードで決済できる。
2. **権利の1行**：決済完了の Webhook を受けて `entitlements` に1行入る（`user_id`, `plan='ume'`, `valid_until`, `source`）。同じ決済イベントを二度受けても1行のまま（冪等）。
3. **買った人だけ開く画面**：`karte.html`（新規・§5 の文言）が、権利のある利用者には「準備中」の中身を表示し、ない利用者には学習カルテの案内（plans-preview へのリンク）だけを表示する。判定はサーバー（`GET /api/session` の応答に `entitlements` を含める）で行い、クライアントの推測で開かない。
4. **9/18 決定の反映：未ログイン＝端末保存／ログイン＝同期。** `ep10-preview.html` の `?server=1` 切替をやめ、常にサーバーモードにする。未ログインでも3問に答えられ、端末内（localStorage）に残る。ログインした時点で、その端末の未送信の回答をサーバーへ送って統合する（既存の `sync.js` の queue を流用。重複は attempt id で防ぐ）。
5. 既存テスト（`npm test`・90件）が通り、Webhook 署名検証・冪等性・権利判定・未ログイン→ログイン時の統合の検証が追加されている。

## 2. 構成（推奨。変えるなら理由を README に書く）

- **Stripe Checkout（hosted）＋ Webhook。** 自前のカード入力画面は作らない。Stripe の Node SDK を使う（`package.json` に追加可）。
- `POST /api/checkout`：ログイン必須（Cookie セッション）。`client_reference_id = userId`、`metadata = { userId, plan: 'ume' }`、`mode: 'payment'`、`line_items` は環境変数 `STRIPE_PRICE_KARTE` の価格1件。`success_url = <origin>/karte.html?checkout=ok&session_id={CHECKOUT_SESSION_ID}`、`cancel_url = <origin>/ep10-preview.html?checkout=cancel`。応答は Checkout の URL だけ（クライアントは `location.href` で遷移）。
- `POST /api/stripe-webhook`：生のボディで署名検証（`STRIPE_WEBHOOK_SECRET`）。`checkout.session.completed` かつ `payment_status === 'paid'` のときだけ `entitlements` に insert。冪等キーは `source = 'stripe:' + session.id`（unique 制約を migration で追加）。利用者が存在しない・metadata が欠ける場合は 200 を返しつつログに残す（Stripe の再送ループを防ぐ）。
- `valid_until`：仮に **2027-10-17T23:59:59+09:00**（2027 本試験日の想定）。環境変数 `ENTITLEMENT_VALID_UNTIL` があればそれを優先。本設計で「加入時期にかかわらず当年度本試験まで」が決まっているので、日付は定数にせず環境変数で持つ。
- `GET /api/session` の応答に `entitlements: [{plan, valid_until}]`（有効期限内のみ）を追加。`GET /api/entitlements` は作らない（往復を増やさない）。
- `karte.html` の判定：ページ読込時に `GET /api/session` → 401 なら「ログイン案内」、200 で `ume` があれば本文、なければ「学習カルテの案内」。`?checkout=ok` で戻ってきた直後は Webhook 未着の可能性があるので、`ume` が無ければ 3 秒間隔で最大 5 回だけ再取得し、それでも無ければ「反映に少し時間がかかっています」を出す（文言は §5）。
- **サーバーモード常時化**（ゴール 4）：
  - `serverMode` を常に true。`?server=1` は受け取っても無視（旧リンク互換）。
  - 未ログイン時：`canAnswer = true`、`progressStore` はこれまで通り localStorage（キーは `mimiobo-guest-v1-ep10-v1` のような固定のゲストキー）。`answerSync` は作らない。画面上の保存先表示は「記録：この端末に保存」（既存の `paintStorageNotes` / `storageScope` の未ログイン文言を使う。文言追加不要）。
  - ログイン成立時（メール・LINE どちらでも）：ゲストキーの attempts を利用者の storageKey へ移し、各回答を `answerSync.enqueue` で送る。移し終えたらゲストキーを消す。サーバー側に同じ attempt id があれば `sync.js` の `merge` の規則（サーバー正）に従う。
  - 既存の「未ログインだと回答ボタン無効」の分岐は削除。`signinPrompt` カードは残す（未ログイン時に表示。文言は変えない）。
- **migration**：`202610060001_sprint2.sql` を追加。`entitlements.source` に unique、必要なら `stripe_events`（event id, received_at）で受信済み記録。RLS は Sprint 1 と同じく service_role のみ。
- **環境変数名**：`STRIPE_SECRET_KEY`（テストキー `sk_test_…`）、`STRIPE_WEBHOOK_SECRET`、`STRIPE_PRICE_KARTE`、`ENTITLEMENT_VALID_UNTIL`。Kei の控えは `_secrets\stripe_takken.env`（中身は読まない・表示しない）。

- ログイン済み・権利あり：h1「学習カルテ」／バッジ「テスト中」／本文「この画面は Sprint 3 で記録から作ります。今は権利の確認だけです。」／事実行「有効期限：{valid_until を YYYY年M月D日 で}」／テキストリンク「3問チェックに戻る」（`ep10-preview.html`）
