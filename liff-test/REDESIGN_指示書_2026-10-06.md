Kei の赤入れ：「全体的にわかりづらい。直感的に操作しづらい。全体の構成が把握しづらいのがストレス」。
memory の原則：ページも設計もシンプルに。文字を足さず減らす。足すのは1〜2個。

## 診断（今の問題）
1. ページ間の道がない（3問チェックから学習カルテへ行けない）。
2. 「カルテ」が2つ（3問チェック内の「今回の結果と復習」画面 `#karte` と、本物の `karte.html`）。
3. ログインの入口が3か所（上部帯の `#connectLine`、`#signinPrompt`、最下部の `#account`）。
4. 開発用の文言が表に出ている（上部帯の「記録：…」「保存中」、「テスト中」バッジ、`preview-links`）。

## 新しい構成（3ページ・1つの共通ヘッダー）

```
共通ヘッダー：耳で覚える宅建 ｜ [3問チェック] [学習カルテ] ……右端に [ログイン] or [ログイン中]
  ├ ep10-preview.html  3問チェック（解く → 結果）
  ├ karte.html         学習カルテ（記録・弱点）
  └ account.html       ログイン（新規。LINE／メール・連携・ログアウト）
フッター：静かに、淡々と。／学習サポートの一覧（plans-preview.html）／教材の確認範囲
```

### 共通ヘッダー（3ページとも同じ HTML・CSS）
- 左：「耳で覚える宅建」（900・15px）。
- 中：タブ2つ「3問チェック」「学習カルテ」。今いるページは水色の下線＋太字（`aria-current="page"`）。スマホでもヘッダー1段に収める（タブ14px）。
- 右：未ログインなら「ログイン」（水色の枠のピル、account.html へ）。ログイン中なら「ログイン中」（薄い灰色の小さなピル、account.html へ）。状態は `GET /api/session` の結果で決める。account.html では右端は出さない。
- `position:sticky;top:0` の白地・下線1px。
- 新規の共通部品ファイル `site-header.js`（UMD でなく素の script でよい）にヘッダーの状態更新をまとめ、3ページから読み込む。dev.cjs の公開ファイルに追加。

### ep10-preview.html（3問チェック）
- 上部のテスト帯 `.preview`（`#storageScope` `#saveStatus` `#retrySave` `#connectLine`）は画面から消す。ただし id は残し、`.preview` を `hidden` 相当の非表示クラスで隠す（JS とテストが参照するため）。保存失敗だけは見せる必要があるので、`#saveStatus` の失敗系の文言が出たときだけ、問題の上に1行の注意（`#saveAlert`、新規、薄い黄色ではなく薄灰の枠）として出す。通常時の「保存しました」「保存中」は出さない。
- `#signinPrompt`（大きい案内カード）は削除相当（非表示・id 維持）。代わりにヒーローの下に1行：未ログイン時のみ「ログインすると、答えた記録が学習カルテに集まります。」＋テキストリンク「ログイン」（account.html?next=ep10）。ログイン中は出さない。
- ヒーロー：オーバーライン「第10回 · 営業保証金と保証協会」／h1「3問チェック」（「定着3問チェック」から短く）／本文「○か×で答えると、すぐに解説が出ます。」／リンク「音声で聴く（約17分）」。進み具合チップ「回答 n / 3」は維持。
- 前回の回答が復元されたときは、チップの横にテキストボタン「最初から解き直す」（既存の `#restart` の処理を呼ぶ）。
- 結果（`#results`）：スコア・3問の○×一覧・復習のひとこと（`#nextTitle` `#nextBody`）はそのまま。その下のボタンを入れ替える：
  - 主ボタン「学習カルテで記録を見る」（karte.html）
  - 副ボタン「もう一度解く」（`#restart`）
  - 「結果と復習を見る」（`#showKarte`）と、その先の画面 `#karte` は**画面からなくす**（ボタン・セクションを非表示・id 維持。`openKarte` は呼ばれなくなる）。`今回の結果はこの端末にだけ残ります` 系の注記 `#resultsStorageNote` は、未ログインのときだけ「この端末にだけ残ります。ログインすると学習カルテに集まります。」、ログイン中は空。
- アカウント欄 `#account` は ep10 から**画面上なくす**（非表示・id 維持）。ログイン処理は account.html へ移す。ただし LINE 連携の戻り（LIFF 経由で ep10 に戻る既存フロー）は壊さないこと：戻ってきたときの自動連携（`verifyLine`）は ep10 側に残す。
- `preview-links` ナビは削除相当（非表示）。plans-preview への導線はフッターへ。

### account.html（新規）
- 共通ヘッダー＋帯1つ＋カード1枚。オーバーライン「アカウント」。
- 未ログイン：h1「ログイン」／本文「記録を別の端末でも見られるようになります。」／主ボタン「LINEでログイン」（既存の LINE ログイン処理）／区切り「または、メールで」／メール入力＋副ボタン「ログインのメールを受け取る」＋注記「届いたリンクを10分以内に開いてください。」
- ログイン中：h1「ログイン中」／事実行「ログインの方法：メール＋LINE」（providers から）／LINE 未連携なら副ボタン「LINEも使えるようにする」（既存 linkLine）／メール未連携なら details「メールも使えるようにする」（既存）／テキストボタン「このブラウザからログアウト」。
- `?next=karte|ep10` があれば、ログイン完了後にそのページへ戻る（メールのリンク経由は auth-callback の戻り先に next を引き継ぐ。難しければ ep10 に戻る既存動作のままでよく、報告に書く）。
- 既存の ep10 のアカウント欄の JS（accountEmailFlow・linkLine・logout・LINE ログイン）を流用。重複が大きければ共通の `account-client.js` に切り出してよい。
- LINE の LIFF 起点の URL（liff.line.me/…/ep10-preview.html）は今のまま。account.html で LINE ログインを押した場合も、LIFF を経由して ep10 に戻ってよい（戻ったらヘッダーが「ログイン中」になる）。

### karte.html（学習カルテ）
- 共通ヘッダー（「学習カルテ」タブが現在地）。
- 未ログイン：h1「学習カルテ」／本文「ログインすると、答えた記録がここに集まります。」／主ボタン「ログイン」（account.html?next=karte）。
- 権利なし：今の文言のまま（テスト決済ボタン）。
- 権利あり：「テスト中」バッジは外す。有効期限は h1 の下の小さい灰色1行に。記録0件のときの主ボタンは「3問チェックを始める」のまま。

### 文言の原則
- 1画面の文言は今より減らす。説明文は1文。
- 開発用の言葉（Sprint・テスト中・保存中・アカウントに保存）は画面に出さない。テスト決済の注記だけは残す。
